## 2. Work Completed (All Verified)

### A. Hero Button URL Resolution (Verified Working by User)
- **Problem:** When switching the button link destination in Admin from "Custom URL" (`/blog`) to "Choose a page" (`/components`), the frontend button still pointed to a fallback dead link `#`.
- **Root Cause:** `hero_component.html.twig` was called inside an include chain with `only` scoping (`hero.html.twig` → layout block with `only` → `hero_component.html.twig` with `only`). The local `page` variable was null/undefined, so `page.find('/components')` failed silently.
- **Fix in `user/themes/basic/templates/partials/hero_component.html.twig`:**
  Replaced `page.find(link_page)` with `grav['pages'].find(link_page)`. In Grav 2.x, `grav` is a Twig global extension accessible even inside `only`-scoped templates, and `grav['pages']` is the global Pages service. Also set fallback to `link_page` directly if `find()` returns null.

### B. Bootstrap Icon Picker in Admin Next (Verified Working by User)
- **Problems:**
  1. Bootstrap icon glyphs rendered as blank square boxes ("tofu") in Admin.
  2. Searching icons (e.g. `house`) gave "No matching icons." and showed "No icon selected".
- **Root Causes:**
  1. In Admin2 (SvelteKit SPA), on root domain installs (`http://grav-base.test/`), `window.__GRAV_CONFIG__.serverUrl` and `window.__GRAV_API_SERVER_URL` are `""` (empty string). Empty string is falsy in JS, causing URL resolution logic to skip the API global and fall back to checking `/admin-next/` in the URL pathname. Because the admin route is `/admin/`, nothing matched, resolving assets to `http://grav-base.test/admin/pages/_hero/user/themes/basic/assets/...`.
  2. Grav's router served the Admin SPA `index.html` (HTTP 200) for that path. Regex searching HTML for `.bi-*:before` matched 0 icons (`[]`).
  3. In JS, `([] || DEFAULT_ICONS)` evaluates to `[]` because an empty array is truthy! Hence `choices` became empty `[]`, breaking all searches.
  4. The browser tried to decode HTML as a WOFF2 font binary, threw a font decode error, and fell back to system fonts (rendering square boxes for private-use icon codepoints).
  5. Shadow DOM isolates `@font-face` rules unless declared in light DOM (`document.head`) or registered in `document.fonts`.
- **Fixes in `user/themes/basic/admin-next/fields/bootstrapiconpicker.js`:**
  - Robust URL resolution: handles `""` for root installs and subfolder paths, checks `window.__GRAV_CONFIG__.serverUrl`, `window.__GRAV_API_SERVER_URL`, and regex-strips `/(admin|admin-next)`.
  - Triple-layer font loading:
    1. Injects `<link rel="stylesheet">` into `document.head` (light DOM).
    2. Loads `bootstrap-icons.woff2` via native `new FontFace('bootstrap-icons', ...)` and adds it to `document.fonts`.
    3. Declares `@font-face` with absolute local URLs and imports stylesheet inside Shadow DOM.
  - Safe catalog loading: ensures response is not HTML before parsing, falls back to `DEFAULT_ICONS` if 0 matches, and never lets an empty array override defaults.
  - In-place DOM updates: builds DOM shell once; search typing updates the grid without wiping `<input>`, preserving focus and query. Added clear (`×`) button to deselect icon.

### G. Text Component Re-designed: One Named Block + Repeatable Blocks
- **Problem (item 3 & 4):** Adding a Text component auto-created three blocks (Eyebrow / Hero Title / Hero Content), each with its own sub-fields. The request was one block whose name the user types, with the styling parameters belonging to the block as a unit, plus the ability to add more blocks.
- **Design decision (important):** "global" parameters cannot include **content** — every block needs its own text. So "global" is implemented as *one uniform field set per block* (`name`, `content`, `tag`, `alignment`, `font_size`, `color`, `margin`, `padding`, `style`), rather than being split across three sub-sections.
- **Implementation:**
  - First block is stored in **flat fields** (`.name`, `.content`, `.tag`) plus the styling fields on the element.
  - Additional text is added manually by adding another `base/text` component to the column's Components list. Each component has its own flat Text fields; there is no nested Additional blocks list in the current blueprint.
  - `name` is an editor-only block label and is not rendered on the frontend. Content and presentation are controlled separately.
  - `tag` selects the rendered element (`p`, `h1`–`h6`, `span`, or `div`); headings get `font-bold` and no forced `leading-relaxed`, matching the original title markup.
- **Legacy fallback retained:** pages still using the old nested `label`/`title`/`text` shape render exactly as before (verified against the original output).

### IMPORTANT — Tooling warning for future sessions
Do **not** rewrite `hero.yaml` with `Symfony\Component\Yaml\Yaml::dump()`. Symfony **expands** YAML anchors on dump, so a round-trip silently turns the single anchored definition back into three literal copies — this is the exact mechanism that produced the drift fixed above. `Yaml::dump($bp, 10, 2)` is byte-identical for this file today, which is why the anchor is applied as a text substitution *after* dumping.
